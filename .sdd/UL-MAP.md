**Maintainer:** James Hsueh

> 本文件只記錄**現在有效的詞彙**，不記錄變更歷史。詞彙不再使用就直接刪除該列。
> 行情本身的詞彙（K 線、交易標的、彙總刻度、策略腳本、交易策略、策略機器人…）由**交易服務**定義，
> 見 `go-trading` 專案的 `.sdd/UL-MAP.md`。本檔**不重述**那些詞，只定義這個外掛自己的。

## 1. Nouns & Concepts

| Domain Term | Technical Name | User-Facing Label | Definition & Business Rules | Status |
| :--- | :--- | :--- | :--- | :--- |
| 交易助理外掛 | *(整個專案)* | 外掛 | 讓助理能代使用者操作**交易服務**的一層。它自己**不存行情、不算指標、不下單、不改任何一條業務規則**——每一件事都轉給交易服務做，外掛只負責轉達，並確認每一次帶來的**外掛授權**。它**不經手密碼、不保管任何人的身分**，所以可以同時跑不只一份 | Confirmed |
| 交易服務 | `ITradingServiceProxy` | 交易服務 | 被代理的那個後端（`go-trading`）。所有業務規則的唯一擁有者。外掛連不到它時，一律明說是「連不到交易服務」，不說成使用者做錯了 | Confirmed |
| 能力 | `ApiToolDomain` | 能力 | 助理做得到的**一件事**，對應交易服務的一件事。每個能力有名稱、說明、要填哪些欄位。每一件都以呼叫端帶來的外掛授權進行，沒有「不需要身分」的能力。清單說的是**外掛真的做得到的**，不是交易服務有的 | Confirmed |
| 能力欄位 | `ToolParameterVo` | 欄位 | 一個能力要填的一格。記著名字、型別、說明、必不必填，以及它在向交易服務轉達時**放到哪裡**（網址上、查詢字串裡、或內文裡） | Confirmed |
| 能力清單 | `apiToolCatalog` | 會做的事 | 外掛所有能力的全集，由組裝根列出。**新增一件事就是在清單補一列**，不改流程。**交易服務內建的行情對話助手刻意不在其中**——代理它等於讓一個 AI 自己決定去花另一個 AI 的錢 | Confirmed |
| 合約能力 | `contractApiTools` | 合約的事 | 永續合約那一條線上的每一件事，共十六件：行情那十五件，加上合約指標計算。**名字一律帶 contract（合約）**、只問得到合約那一條線；現貨的能力一件都不帶、一件都不會問到合約那一條線——同一個代號在兩邊是兩種商品，拿錯不會被拒絕，只會回一份看起來正常、講的是另一件事的數字。 | Confirmed |
| 合約行情格教學 | `contractKCandleScriptNote` | — | 一支吃合約行情的算式收到什麼、每一格有什麼、沒有值時是什麼。**只寫一份**，建立／修改策略腳本與合約指標計算兩處都用它——助理在兩處讀到兩種說法，寫出來的算式就只對得上其中一種 | Confirmed |
| 連線 | *(傳輸的一段往來)* | 這次連線 | 助理與外掛之間的一段往來。**不再承載身分**——身分跟著每一次呼叫帶來的外掛授權走；落到另一份外掛時重開一段往來即可，不必重新授權 | Confirmed |
| 外掛授權 | `ConnectorAuthorizationDomain` | 外掛授權 | 使用者在交易服務網站上按下「允許」後，由授權伺服器發給 Claude Code 的一份身分證明，每一次呼叫都在請求標頭裡帶來。外掛**只確認、不保管**：由交易服務確認它有效、使用者還在、而且**發給的對象正是這個外掛**（對象比對時結尾斜線不計）。續用由 Claude Code 自己向授權伺服器處理，外掛不參與；外掛授權絕不出現在回覆或紀錄裡 | Confirmed |
| 授權伺服器 | *(交易服務的外掛授權功能)* | 交易服務 | 發外掛授權的一方，就是交易服務本身。外掛在授權說明裡以**交易服務的公開位址**指向它 | Confirmed |
| 授權說明 | `ProtectedResourceMetadata` | — | 外掛公開的一份說明：這個外掛的正式位址、授權要向誰拿、授權放在標頭裡。沒有外掛授權的呼叫被拒時，回覆會指出這份說明在哪裡，Claude Code 靠它自己走瀏覽器登入 | Confirmed |
| 外掛的正式位址 | `PUBLIC_BASE_URL` + `MCP_PATH` | — | 外掛對外的位址，即外掛授權必須發給的對象。**由設定給，不從請求推算**——正式環境前面的轉送會改寫來源資訊 | Confirmed |
| 交易服務的公開位址 | `TRADING_SERVICE_PUBLIC_URL` | — | 使用者的瀏覽器與 Claude Code 看得到的交易服務位址，寫在授權說明裡；與外掛自己連交易服務用的內部位址不同 | Confirmed |
| 授權確認結果 | `ConnectorAuthorizationVerdictRepository` | — | 一份外掛授權確認過的結果，以授權的**指紋**記住（不記授權本身），最多一分鐘、且不超過授權本身的到期時刻；問不到交易服務的結果不記 | Confirmed |
| 代辦結果 | `ToolResultDto` | 回覆 | 一次代辦的產出：做成了就是交易服務回的內容；沒做成就是**交易服務原話的拒絕原因**，或「連不到交易服務」，或「請到 Claude Code 的外掛選單重新連線」 | Confirmed |
| 做不成的原因 | `FailureReasonDomain` | 為什麼沒做成 | 一次代辦沒做成時，判斷它要讀者做哪一件事：重新連線、改一改再送、或等一下再送同一件事。**這幾句話絕不共用**——把「網路不通」說成「請重新連線」，代價是使用者白走一次瀏覽器登入 | Confirmed |
| 呼叫端 | `mcpCaller` | — | 一次呼叫的另一端是誰。答案（帶來的外掛授權）只從呼叫本身的封套讀，**絕不從助理填的欄位讀**——填得出自己身分的表單，就填得出別人的 | Confirmed |
| 即時更新快照 | `LiveUpdateSnapshotDto` | 看一眼 | 即時更新只給看一眼：收到第一則就回，最長等一段上限時間。等滿仍沒有東西是**正常結果**，不是失敗 | Confirmed |
| 合約歷史同步的持倉統計 | *(交易服務的能力)* | 持倉統計那一份 | 交易服務的合約歷史同步**補完合約 K 線後，同一趟以同一個回溯天數從持倉統計歷史資料庫一天一天補持倉統計**，只存沒有的。輪次上另有一組 `positionStatistic`（共幾天、走到第幾天、存了幾筆、跳過幾筆、歷史資料庫不答話的原因），**與合約 K 線那組分開、不加總**。沒有那一天的檔案不算失敗；歷史資料庫不答話只停下持倉統計那一份、輪次照樣成功。外掛只負責在說明裡講清楚這些，助理才不會回答使用者「三十天以前補不了」 | Archeology |
| 推定休市天數 | *(交易服務的能力)* | `presumedClosedDayCount` | 交易服務的**現貨**歷史同步問到某一個平日、行情來源說「這一天沒有這個標的的資料」（多半是交易日曆不認得的國定假日）時，**那一天被跳過、同步繼續往下**，輪次上記一天。**不算來源不答話**；與略過根數（來源答了、某幾根不合格）是兩件事。外掛只負責在兩個現貨歷史同步能力的說明裡講清楚，助理才不會把「完成但存得少」回報成故障。合約沒有休市日，不提 | Confirmed |

| 幣安交易金鑰 | *(交易服務的詞)* | 幣安交易金鑰 | 使用者自己留在交易服務的一組幣安 API Key 與 Secret Key，可以動用他的真錢。**外掛只讀得到「有沒有設定、可交易市場、設定時刻」**，讀不到任何一段金鑰內容（連 API Key 結尾都沒有），也**沒有**存入、更換、移除它的能力——只能請使用者到網頁的設定頁自己做；不要求使用者把金鑰貼進對話，貼了也不複述、不轉送。**與 Telegram 的「機器人金鑰」是兩件事，不得混用** | Confirmed |
| 可交易市場 | `tradableMarkets` | 可交易市場 | 存下幣安交易金鑰當時，幣安說它開了哪幾種交易權限：現貨、合約，或兩者。尚未設定時為空；外掛照交易服務的原話說出，不推算 | Confirmed |
| 自動下單 | `autoOrderEnabled` | 自動下單 | 每台策略機器人（現貨與合約）上的一個開關，表達是否允許用幣安交易金鑰替使用者下單。**目前開著也還不會下單**，機器人仍只送 Telegram 通知。外掛只讀得到它是開是關；**沒有**打開或關掉它的能力，建立或修改機器人也不帶、不轉送它——只能請使用者到網頁的機器人詳細頁自己做 | Confirmed |
---
| 重演 | *(交易服務的能力)* | 重演 | 交易服務照一套規則把一段行情走一遍。**現貨重演只做現貨**：買入時空手就開倉、已經有倉位就當作沒聽到；賣出就平倉把錢收回來、之後空手；空手時聽到賣出什麼都不做——所以它沒有模式可挑、沒有槓桿可開。借錢、做空與強制平倉在**合約重演**，遇到那種要求要**指向合約重演**，不要替使用者在現貨重演裡換一組設定去湊 | Confirmed |
| 合約重演 | *(交易服務的能力)* | 合約回測 | 交易服務在**逐倉合約帳戶**上重演一支吃合約行情的策略腳本或一份合約交易策略：可多可空、槓桿、以標記價格判強平、一律計入資金費率、遵守交易規格、可選滑點。兩件能力共用**一份**條件清單與**一份**帳戶說明 | Confirmed |
| 合約交易模式 | *(交易服務的詞)* | 交易模式 | 多空反手／只做多／只做空。重演一支合約腳本時由那一次說；**合約交易策略記在自己身上，重演它時不能給**；K 線交易策略沒有交易模式 | Confirmed |
| 機器人行情種類 | *(交易服務的詞)* | 行情種類 | 一台策略機器人吃哪一種行情：K 線（**現貨機器人**）或合約行情（**合約機器人**）。建立時不說即現貨；修改時不說即保留，換成另一種被拒絕。外掛**不說就不送**，不替助理填上 K 線——否則合約機器人改個名字會被當成要換種類 | Confirmed |
| 機器人槓桿倍數 | *(交易服務的詞)* | 槓桿 | 建議部位那一組裡的一格，**只有合約機器人收**；不給即一倍。與合約重演的槓桿倍數**同名不同事**：那個跟著一次重演走，這個存在機器人身上、決定每一輪建議的名目 | Confirmed |
| 合約機器人的建議部位 | *(交易服務的詞)* | 建議部位 | 合約機器人每一輪建議押多少、停在哪裡，**照交易所規則算**：數量照步進取整、止損止盈對齊價格跳動單位、附預估強平價（名目所在那一級）與資金費率成本估算；交易所不收（數量／名目不足、那一級最高槓桿不夠）時，保證金那一行照寫（未取整），接著只有一行不收的原因與它的數字，不給數量、止損止盈、強平價與資金費率。做多的預估強平價在零以下時改寫「這個槓桿下不會被強制平倉」。合約標的還沒有交易規格時不取整、不估強平價。**外掛不算任何一個數字**，說明只負責讓助理讀懂 | Confirmed |
| 執行紀錄的方向、槓桿、名目 | *(交易服務的詞)* | 方向／槓桿／名目 | 合約機器人那一輪有建議部位時，執行紀錄多帶的三樣；現貨機器人與交易所不收的那一輪沒有。開倉金額是保證金；那個合約標的有交易規格時是取整後的數字，沒有交易規格時、以及這個功能上線前的紀錄是未取整的（更早的紀錄也沒有這三樣） | Confirmed |
| 成交時點 | *(交易服務的詞)* | 成交時點 | 一次重演裡信號在什麼價格成交：收盤成交（預設）或下一格開盤成交。研發短線策略時外掛引導助理用下一格開盤成交 | Confirmed |
| 驗證起點 | *(交易服務的詞)* | 驗證起點 | 把一次重演切成調參段與驗證段的時刻；兩段各自從空手重演、各一張成績單。外掛引導助理**只在調參段調參、只以驗證段判斷** | Confirmed |
| 重演等待時間 | `TRADING_SERVICE_REPLAY_TIMEOUT_SECONDS` | — | 外掛替四件重演能力與兩件實盤 vs 回測能力（合約、現貨）等交易服務回覆的時間，預設一百二十秒，刻意長於交易服務九十秒的整次允許時間；其他能力照舊用一般等待時間 | Confirmed |
| 精簡重演結果 | *(尚未實作)* | — | 四件重演的成功回覆交給助理前：資金曲線最多兩百點（平均取樣、頭尾必留）、交易明細只留最近一百筆並說出總數；分段的兩張各自照做；成績單數字一個不動。看不懂的回覆原封轉交 | Confirmed |
| 合約交易日誌能力 | *(尚未實作)* | 交易日誌的事 | 合約那一條線上代使用者操作**合約交易日誌**的每一件事：記一筆、加倉／減倉／平倉與修改、刪除紀錄、修改進場計畫、加附註、寫檢討、列出與查看交易、看績效統計、看實盤 vs 回測、列出／新增／改名／刪除標籤、看與設定手續費率、刪除交易。**名字一律帶合約**。業務規則（一標的一方向一筆持倉中、不能反手、平倉後鎖定、統計口徑）全由交易服務決定，外掛不檢查、不算任何數字 | Confirmed |
| 口述成交 | *(尚未實作)* | 開倉／平倉（合約）、買進／賣出（現貨） | 使用者說出的實際成交：價、量、時間。合約那一本一律稱開倉、加倉、減倉、平倉與開倉價、平倉價，不說「成交」；現貨那一本稱買進、賣出。**必須是使用者說的**——機器人訊息裡的參考價不是成交價，只貼訊息沒說成交價時助理先問，不記 | Confirmed |
| 預設成交時間 | *(尚未實作)* | 成交時間 | 使用者沒說成交時間時以**現在**為準；說了時間以他的時區理解；回覆一律以使用者時區說出記下的時間請他確認。無從得知時區時以台北時間為預設並說出 | Archeology |
| 列出交易的預設筆數 | *(尚未實作)* | — | 列出交易沒說筆數時回開倉（現貨為第一筆買進）最新的 **20 筆**，並說出總數、可以要更多 | Archeology |
| 刪除前確認 | *(尚未實作)* | — | 刪除一筆合約交易前，助理先向使用者確認是哪一筆；指的不只一筆時列出請使用者指定，不猜 | Archeology |
| 現貨交易日誌能力 | *(尚未實作)* | 現貨交易日誌的事 | 現貨那一條線上代使用者操作**現貨交易日誌**（加密貨幣現貨與台股）的每一件事：記一筆、加／修正／刪除買賣、修改進場計畫、加附註、寫檢討、設定型態標籤、列出與查看、看現貨統計、看現貨實盤 vs 回測、刪除。**名字一律帶現貨**，與合約日誌能力各自一組；標籤與合約共用。現貨只有先買後賣、沒有槓桿 | Confirmed |
| 一張換算 | *(尚未實作)* | 一張 | 使用者說台股「一張」時換算為 **1,000 股**，並說出換算後的股數請使用者確認；說零股就照股數。台股數量必須是整數股 | Confirmed |
| 同代號先問 | *(尚未實作)* | — | 使用者說的代號同時是加密貨幣現貨與合約標的（如 BTCUSDT）而沒說是哪一本時，助理先問現貨還是合約，得到回答前不送出 | Confirmed |

## 2. Actions & Processes

| Business Action | Technical Method | Trigger | Business Impact | Notes |
| :--- | :--- | :--- | :--- | :--- |
| 列出會做的事 | `ListTools` | 助理問外掛會什麼 | 回覆能力清單全集 | 一樣要有外掛授權 |
| 代辦一件事 | `CallTool` | 助理要求做一件事 | 依該能力的定義、帶著這一次的外掛授權向交易服務轉達，把結果或拒絕原因帶回 | 交易服務不認得身分時請使用者重新連線，不重試 |
| 確認外掛授權 | `VerifyConnectorAuthorization` | 每一次呼叫進到外掛 | 向交易服務確認外掛授權有效、使用者還在、發給這個外掛；不通過即不接待並指出授權說明 | 問不到交易服務時說「暫時連不到交易服務」，不說成授權失效 |
| 瀏覽器登入 | *(Claude Code 與授權伺服器之間)* | 使用者在 Claude Code 外掛選單按「連線」 | 瀏覽器打開交易服務網站，使用者登入並允許，Claude Code 拿到外掛授權 | 外掛不參與，只提供授權說明 |
| 看一眼即時更新 | `PeekLiveUpdates` | 助理想看某標的現在的樣子 | 收下即時更新到第一則或等滿上限為止，然後收掉連線 | 絕不維持一條永遠開著的通道 |
| 看一眼合約即時更新 | `trading_peek_live_contract_k_candle` | 助理想看某個合約標的現在的樣子 | 與看一眼即時更新同一種看法，但只看合約那一邊、只看得到合約追蹤名單上的合約標的；內容是最新價，不含標記價格；走完的那一根由每分鐘那一輪存入 | 不在合約追蹤名單上即被拒絕；絕不維持一條永遠開著的通道 |

## 3. Ambiguities & Conflicts

| Ambiguous Term | Meaning in Context A | Meaning in Context B | Resolution |
| :--- | :--- | :--- | :--- |
| 授權不通過 | 外掛授權失效、或不是發給這個外掛 | 問不到交易服務來確認 | 前者不接待並指出授權說明，Claude Code 會帶使用者重新授權；後者說「暫時連不到交易服務」。**兩者絕不共用同一句話** |
| 做不成 | 交易服務拒絕（規則不通過、不是你的、額度用完） | 外掛連不到交易服務 | 前者原話轉述交易服務的說法；後者明說「連不到交易服務」。混在一起會害人去改沒有錯的東西 |
| 沒有東西 | 看一眼即時更新，等滿仍無更新 | 那個標的分不到即時名額 | 前者是正常結果、等一下會有；後者要人去改觀察清單才會好 |
| 停損距離／停利距離 | 一台機器人身上那一格（`positionPlan` 裡） | 一次重演的參數（`stopLossPercentage`） | **同名，不同事。** 機器人那一格說的是「每一輪要建議什麼」，從最新價量起、存在機器人身上；重演那一個說的是「這一次要怎麼模擬」，從**進場價**量起、跟著這一次呼叫走、不留存。兩個能力的說明都各自寫明自己是哪一個——助手手上同時握著這兩組數字，而它們長得一模一樣 |
| 「進場價」 | 機器人訊息裡的參考價 | 使用者實際成交的價格 | 日誌只收使用者說的成交價；助理不得拿參考價充當，只貼訊息時先問實際成交價 |
| 「成交」 | 合約那一本的每一筆紀錄 | 現貨那一本的每一筆紀錄 | 合約稱開倉、加倉、減倉、平倉與開倉價、平倉價；現貨稱買進、賣出與買進價、賣出價。合約能力的說明不再出現「成交」 |
