# Product Requirements Document (PRD) — 助理養得起合約策略機器人

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh

---

## 1. Background & Goal

- **Problem Statement:** 交易服務的策略機器人分成現貨機器人與合約機器人，但外掛的說明還寫著
  「策略機器人只跑 K 線、掛不上吃合約行情的交易策略」「沒有槓桿這一項」。助理因此會告訴使用者做不到，
  或把合約交易策略改寫成現貨的去湊。
- **Expected Outcome:**
  - 助理建機器人時說得出它是現貨還是合約；不說即現貨，照舊的寫法不變。
  - 修改機器人時不提種類就保留，說明寫明「這一格不像其他欄位，沒帶不會清掉」。
  - 合約機器人的建議部位收槓桿倍數；說明寫明兩種機器人各收什麼、會因為什麼被拒絕。
  - 列出機器人時可以只列一種；讀回來分得出兩種。
  - 別處「機器人掛不上合約」的說法消失，改成指向合約機器人。
- **Out of Scope:** 為合約機器人另開一組名字不同的能力；外掛自己檢查行情種類、名單或槓桿；
  啟動、停止、刪除、立刻跑一輪、執行紀錄的說法（兩種共用、不變）。

---

## 2. User Personas

- **Primary Role:** 代使用者操作交易服務的助理（使用者本人透過它說話）。
- **Usage Context:** 使用者拼好並重演過一份合約交易策略後說「幫我開一台機器人盯 BTCUSDT 永續，五倍」。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 建機器人時說出它是哪一種 [P0]

**As a** 助理, **I want** 建機器人時說出它吃哪一種行情, **so that** 我建得出合約機器人，也不會把現貨的弄錯。

```gherkin
Scenario: 建一台合約機器人
  Given 一份吃合約行情的交易策略、BTCUSDT 在合約追蹤名單上
  When 助理建一台機器人並說它吃合約行情
  Then 送往交易服務的內容帶著「合約行情」這個種類
  And 建立機器人的說明寫出合約機器人只能引用吃合約行情的交易策略、標的要先在合約追蹤名單上

Scenario: 沒說種類即現貨
  Given 一份吃 K 線的交易策略
  When 助理建一台機器人、沒說種類
  Then 送往交易服務的內容裡沒有種類這一項
  And 說明寫出不給就是現貨機器人（K 線）

Scenario: 種類與交易策略不符由交易服務拒絕
  Given 一份吃合約行情的交易策略
  When 助理建一台機器人、沒說種類
  Then 交易服務的拒絕原話原樣帶回給助理

Scenario: 標的不在合約追蹤名單上由交易服務拒絕
  Given DOGEUSDT 不在合約追蹤名單上
  When 助理建一台合約機器人盯 DOGEUSDT
  Then 交易服務的拒絕原話原樣帶回
  And 說明事先寫出這種情況要先把標的加進合約追蹤名單
```

### US-02 — 修改時保留種類 [P0]

**As a** 助理, **I want** 改機器人時不必重帶種類, **so that** 我改個名字不會被當成要換種類。

```gherkin
Scenario: 只改名字不帶種類
  Given 一台合約機器人
  When 助理只改名字、沒提種類
  Then 送往交易服務的內容裡沒有種類這一項
  And 修改機器人的說明寫出種類不給就是保留原本的、換成另一種會被拒絕

Scenario: 換種類由交易服務拒絕
  Given 一台現貨機器人
  When 助理把種類改成合約行情
  Then 送往交易服務的內容帶著「合約行情」
  And 交易服務的拒絕原話原樣帶回
```

### US-03 — 合約機器人的槓桿 [P0]

**As a** 助理, **I want** 替合約機器人設槓桿, **so that** 它每一輪建議的名目與保證金對得上使用者要的倍數。

```gherkin
Scenario: 給合約機器人槓桿
  Given 一台合約機器人
  When 助理在建議部位裡給槓桿 5
  Then 槓桿 5 跟著建議部位原樣送出
  And 建議部位的說明寫出槓桿只有合約機器人收、不給即一倍、小於一或超過標的上限會被拒絕

Scenario: 不給槓桿
  Given 一台合約機器人
  When 助理的建議部位裡沒有槓桿
  Then 送出的建議部位裡沒有槓桿這一項

Scenario: 槓桿小於一
  Given 一台合約機器人、槓桿 0.5
  When 送出
  Then 交易服務的拒絕原話原樣帶回

Scenario: 現貨機器人給槓桿
  Given 一台現貨機器人、槓桿 3
  When 送出
  Then 交易服務的拒絕原話原樣帶回
  And 建議部位的說明事先寫出現貨機器人給大於一倍的槓桿會被拒絕
```

### US-04 — 讀回來分得出兩種 [P1]

**As a** 助理, **I want** 列機器人時只列一種, **so that** 使用者問「我的合約機器人」時我不必自己篩。

```gherkin
Scenario: 只列合約機器人
  Given 兩台現貨、一台合約
  When 助理只列合約機器人
  Then 向交易服務問的是「只要合約行情那一種」
  And 列出機器人的說明寫出可以只列一種、每一台都帶著自己的種類

Scenario: 不指定即全部
  Given 兩台現貨、一台合約
  When 助理列出機器人、不指定種類
  Then 向交易服務問的時候沒有帶種類
```

### US-05 — 別處不再說「機器人掛不上合約」 [P1]

**As a** 助理, **I want** 建交易策略與寫合約策略腳本的說明指向合約機器人, **so that** 我不會告訴使用者做不到。

```gherkin
Scenario: 建交易策略的說明
  When 助理讀建交易策略的說明
  Then 說明寫出吃合約行情的交易策略可以掛上合約機器人
  And 說明不再寫「策略機器人目前掛不上它」

Scenario: 合約算式教學
  When 助理讀合約算式教學
  Then 教學寫出吃合約行情的交易策略可以掛上合約機器人
  And 教學不再寫「策略機器人目前只跑 K 線」
```

## 4. Business Flow & Logic

- 外掛只轉達：沒填的欄位不送；交易服務的拒絕原話原樣帶回。
- 種類與槓桿都是選填欄位；外掛不替任何一格填預設值。
