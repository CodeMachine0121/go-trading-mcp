**Owner:** James Hsueh
**Stakeholders:** Engineering, QA

## 1. Background & Goal

### Problem Statement

交易服務的重演**只做現貨了**——借錢、做空與強制平倉整組移出，
因為它們描述的是合約帳戶上的事，而那是另外一件事。

**這個外掛是助手看見那個服務的唯一窗口**，而它的工具目錄還在提供三樣不存在的東西：
一份交易策略「寫給哪一種帳戶」、一次重演「借幾倍」與「維持保證金率」、
一台機器人的建議部位「上幾倍槓桿」。

目錄過期的代價與後端漏改一格不同：助手不是讀文件，是**照著目錄行動**。
它會挑一個模式送出去、替使用者算一個五倍的部位、在成績單上找一格不存在的數字——
每一次都被整份拒絕，而它只看到一句它不理解的話，於是換個寫法再試。

**更糟的是目錄講得出口。** 裡面有大段文字教它
「合約帳戶只做多要給 leveragedLong」「開了槓桿一定要一起給止損」。
那些句子現在是**錯的建議**，而它們讀起來仍然非常有道理——
使用者會據此以為這個服務支援一件它已經不做的事。

### Expected Outcome

- **助手看不到那三樣東西**，因此也送不出——不是送出去才被擋。
- **目錄主動說出**重演只做現貨，以及使用者提到放空或槓桿時該怎麼回。
- **成績單的描述與成績單本身一致**：不再提那一格已經不存在的數字。
- **工具一支都沒少**——這一刀移除的是參數與句子，不是能力。
- 與重演無關的每一支工具逐字不變。

### Out of Scope

- **合約的重演。** 交易服務那邊是另外一刀；等它有了自己的工具，再回到這份目錄。
- 止損、止盈、交易成本、倉位大小模式——完整保留。
- 任何一支工具的存廢與路由。
- 這個外掛自己的登入、工作階段、錯誤處理。
- 在這個外掛裡**再擋一次**那三個欄位（見 §4 R4）。

## 2. User Personas

- **Primary Role:** 透過助手操作交易服務的那個人——本系統唯一的使用者。
  他不讀這份目錄，他讀的是助手照著目錄給他的答案。
- **Secondary Role:** 助手本身。它是這份目錄唯一的直接讀者，
  而它對這個服務的認識**完全來自這份目錄**——沒寫的它不知道，寫錯的它照做。
- **Usage Context:** 對話中請助手拼策略、跑重演、養機器人。

## 3. User Stories & Acceptance Criteria

### US-01 — 助手挑不到一個不存在的選項 [priority: P0]

**As a** 助手，
**I want** 工具目錄上沒有「寫給哪一種帳戶」這一格，
**so that** 我不會替使用者挑一個送出去必定被拒絕的值。

```gherkin
Scenario: 建立交易策略的工具沒有這一格
  Given 建立交易策略那一支工具
  When 讀它的參數清單
  Then 看得到名稱、信號來源、買入條件與賣出條件
  And 沒有任何一格是在問這份規則寫給哪一種帳戶

Scenario: 修改交易策略的工具與建立那一支一致
  Given 修改交易策略那一支工具
  When 讀它的參數清單
  Then 參數與建立那一支逐項相同,同樣沒有那一格

Scenario: 重演一支策略腳本的工具沒有這一格
  Given 重演一支策略腳本那一支工具
  When 讀它的參數清單
  Then 沒有任何一格是在問這一次照哪一套規則交易
```

### US-02 — 助手開不了一個借不到的槓桿 [priority: P0]

**As a** 助手，
**I want** 重演與機器人的參數清單上都沒有槓桿，
**so that** 我不會替使用者算一個這個服務模擬不出來的部位。

```gherkin
Scenario: 重演一支策略腳本不再問借幾倍
  Given 重演一支策略腳本那一支工具
  When 讀它的參數清單
  Then 沒有一格在問借幾倍,也沒有一格在問維持保證金率
  And 起訖、資金、倉位大小、止損止盈與兩個成本率照舊都在

Scenario: 重演一份交易策略不再問借幾倍
  Given 重演一份交易策略那一支工具
  When 讀它的參數清單
  Then 沒有一格在問借幾倍,也沒有一格在問維持保證金率

Scenario: 機器人的建議部位剩四樣
  Given 建立機器人那一支工具
  When 讀建議部位那一格的說明
  Then 說明列出資金、倉位大小模式與數值、停損距離、停利距離
  And 說明裡沒有槓桿這一項

Scenario: 修改機器人與建立那一支一致
  Given 修改機器人那一支工具
  When 讀建議部位那一格的說明
  Then 說明與建立那一支逐字相同
```

### US-03 — 助手知道這個服務做什麼、不做什麼 [priority: P0]

**As a** 使用者，
**I want** 我說要放空或上槓桿時，助手直接告訴我這個服務不做那件事，
**so that** 它不會替我換一組設定去湊，然後給我一張照著我做不到的操作算出來的成績單。

```gherkin
Scenario: 目錄說出重演怎麼走倉位
  Given 重演那一支工具的說明
  When 讀它
  Then 說明寫著重演只做現貨
  And 說明寫著買入時空手就開倉、賣出就平倉回現金、空手時聽到賣出什麼都不做

Scenario: 目錄說出這裡做不到什麼
  Given 重演那一支工具的說明
  When 讀它
  Then 說明寫著這裡沒有交易模式可指定,也開不了槓桿

Scenario: 目錄說出遇到那種要求該怎麼回
  Given 重演那一支工具的說明
  When 讀它
  Then 說明要助手直接說這個服務只重演現貨
  And 說明要助手不要替使用者換一組設定去湊

Scenario: 舊的挑模式指引整段不見
  Given 任何一支工具的說明
  When 在裡面找挑交易模式的指引
  Then 找不到「合約帳戶只做多給 leveragedLong」這類句子
  And 找不到 longShort、leveragedLong、shortOnly 這三個詞
```

### US-04 — 成績單的描述與成績單本身一致 [priority: P1]

**As a** 助手，
**I want** 說明只提成績單上真的有的那幾格，
**so that** 我不會去找一個不存在的數字，也不會照它給出一段沒有根據的解讀。

```gherkin
Scenario: 不再提那一格已經不存在的數字
  Given 重演那一支工具的說明
  When 在裡面找「這次歸零過幾次」那一格
  Then 找不到

Scenario: 還在的那幾格照舊被提到
  Given 重演那一支工具的說明
  When 在裡面找止損出場筆數與累計成本
  Then 兩者都還在,措辭與這一刀之前逐字相同

Scenario: 進場成本照押下去的金額收
  Given 進場成本那一格的說明
  When 讀它是照什麼收的
  Then 說明說它照押下去的金額收
  And 說明不再提曝險金額,也不再說開了幾倍就收幾倍
```

### US-05 — 與重演無關的工具一支都不動 [priority: P0]

**As a** 使用者，
**I want** 這一刀只碰重演這件事，
**so that** 我正在用的行情查詢、腳本管理、機器人與通知不會被它波及。

```gherkin
Scenario: 工具一支都沒少
  Given 這一刀之前的工具清單
  When 這一刀做完之後再讀一次
  Then 工具的支數與名稱逐項相同

Scenario: 無關的工具逐字不變
  Given 行情、策略腳本、機器人生命週期與通知那幾支工具
  When 這一刀做完之後讀它們的參數與說明
  Then 與這一刀之前逐字相同
```

## 4. Business Flow & Logic

### Core Business Rules

**R1 — 從目錄上消失的三樣**

| 工具 | 消失的 |
| :--- | :--- |
| 建立交易策略 · 修改交易策略 | 寫給哪一種帳戶 |
| 重演一支策略腳本 | 照哪一套規則交易、借幾倍、維持保證金率 |
| 重演一份交易策略 | 借幾倍、維持保證金率 |
| 建立機器人 · 修改機器人 | 建議部位裡的槓桿 |

**消失＝助手看不到**。工具 schema 是封閉的，看不到就送不出。

**R2 — 目錄要主動說出的三件事**

1. 重演只做現貨，以及買入／賣出／空手時賣出各自會發生什麼。
2. 這裡沒有交易模式可指定，也開不了槓桿——借錢、做空與強制平倉是合約帳戶的事。
3. 使用者提到那些事時，直接說這個服務只重演現貨，**不要替他換一組設定去湊**。

**R3 — 說明與回應要一致**

說明只提成績單上真的有的格子。提一個不存在的，
助手會去找它、找不到，然後照著自己對「它應該在」的印象作答。

**R4 — 這個外掛不自己再擋一次**

那三個欄位在目錄上不存在，助手送不出來。萬一真的送了，
交易服務會整份拒絕並說出理由，而那句理由原樣交回助手。
**兩處各擋一次，就是兩句話等著分岔**——這與交易服務那一邊「一句話只有一份」是同一條理由。

### Edge Cases

- **助手拿著舊的對話脈絡再送一次那三個欄位**：目錄已經沒有它們，
  送出去由交易服務拒絕，助手收到的是服務自己的說法。這個外掛不介入。
- **工具說明被截斷**：說明是純文字，沒有長度上限的處理；這一刀只讓它變短。

## 6. Non-Functional Requirements

- **相容性：** 工具的支數、名稱與路由一律不變，只有參數與說明變少。
  正在用這個外掛的對話不會因為這一刀而斷。
- **一致性：** 目錄描述的每一件事，交易服務那一邊都真的做得到——
  這正是這一刀存在的理由，也是它唯一的驗收標準。

## 7. Dependencies & Risks

### Dependencies

- **交易服務的 `2026-09-22-spot-only-backtest`。** 這份目錄描述的是那一刀之後的服務。
  兩者之間沒有版本協商：目錄先改或後改都不會壞，只會在那段期間給出過期的建議。

### Known Risks

| 風險 | 說明 | 處置 |
| :--- | :--- | :--- |
| **目錄與服務再度分岔** | 這一刀之所以必要，正是因為上一次分岔了 | 驗收標準綁在「服務端做得到什麼」，不綁在「目錄看起來合理」 |
| **助手的舊脈絡** | 同一段對話裡它可能還記得舊欄位 | 接受：服務端會拒絕並說出理由，而那是它學到新事實的正常途徑 |
