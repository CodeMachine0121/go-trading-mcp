# Product Requirements Document (PRD) — 幣安自動下單設定（外掛只讀）

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh
**Stakeholders:** 交易服務（`go-trading` 同名切片，業務規則的唯一來源）、操作台（`go-trading-frontend` 同名切片）

---

## 1. Background & Goal

- **Problem Statement:** 交易服務新增了使用者自己的一組**幣安交易金鑰**，以及每台策略機器人上的**自動下單**開關（這一刀還不會真的下單）。
  外掛今天看得到機器人，卻說不出哪一台開著自動下單、也說不出使用者有沒有設定幣安交易金鑰；
  而且若不明確劃線，助理可能會在對話裡向使用者要金鑰、或想替使用者把自動下單打開。
- **Expected Outcome:**
  - 查看或列出策略機器人（現貨與合約）時，助理說得出每一台的**自動下單**是開是關，並補一句「目前開著也還不會下單，機器人仍只送 Telegram 通知」。
  - 使用者問起時，助理說得出他**有沒有**設定幣安交易金鑰、**可交易市場**是現貨、合約或兩者；不給任何一段金鑰內容。
  - 助理在使用者要求設定金鑰或切換自動下單時，指引他到網頁的設定頁或機器人詳細頁自己做；不要求、不複述、不轉送任何金鑰。
  - 建立或修改機器人不會改動它的自動下單。
- **Out of Scope:**
  - 存入、更換、移除幣安交易金鑰；打開或關掉自動下單（包括「只能關、不能開」）。
  - 下單相關的任何能力。
  - 外掛自己判斷金鑰的可交易市場是否涵蓋某台機器人（那是交易服務在網頁上打開時的規則）。

---

## 2. User Personas

- **Primary Role:** 代使用者操作交易服務的助理（使用者本人透過它說話）。
- **Usage Context:** 使用者在 Claude Code 裡問「看一下我的機器人」「我設定幣安了嗎」「幫我把自動下單打開」；偶爾會把金鑰直接貼進對話。

---

## 3. User Stories & Acceptance Criteria

以下若無特別說明：使用者帶著有效的外掛授權。

### US-01 — 看得到機器人的自動下單 [P0]
**As a** 使用者, **I want** 查看機器人時知道自動下單是開是關, **so that** 我清楚哪幾台將來會用真錢下單。

```gherkin
Scenario: 列出機器人時標出自動下單（例 1）
  Given 合約機器人甲的自動下單開著
  When 使用者說「看一下我的機器人」
  Then 回覆列出甲並標出「自動下單：開」
  And 補一句「目前開著也還不會下單，機器人仍只送 Telegram 通知」

Scenario: 查看單一台也看得到
  Given 現貨機器人丙的自動下單關著
  When 使用者問「丙的設定是什麼」
  Then 回覆標出「自動下單：關」
```

### US-02 — 知道自己有沒有設定幣安交易金鑰 [P0]
**As a** 使用者, **I want** 問助理我設定幣安了沒, **so that** 我不必自己開網頁查。

```gherkin
Scenario: 已設定（例 2）
  Given 使用者已設定幣安交易金鑰，可交易市場：現貨
  When 使用者問「我設定幣安了嗎」
  Then 回覆「已設定，可交易市場：現貨」
  And 回覆不含 API Key 或 Secret Key 的任何一個字，連結尾也沒有

Scenario: 尚未設定（例 3）
  Given 使用者尚未設定幣安交易金鑰
  When 使用者問「我設定幣安了嗎」
  Then 回覆「尚未設定」
  And 指引他到網頁的設定頁自己設定
```

### US-03 — 寫入只在網頁上做 [P0]
**As a** 使用者, **I want** 助理不碰我的金鑰也不替我打開自動下單, **so that** 金鑰不留在對話紀錄裡，用真錢下單由我親手按。

```gherkin
Scenario: 要求打開自動下單（例 4）
  When 使用者說「幫我把甲的自動下單打開」
  Then 助理說明這件事只能在網頁的機器人詳細頁自己做
  And 不送出任何改動

Scenario: 在對話裡貼出金鑰（例 5）
  When 使用者在對話裡貼出一組 API Key 與 Secret Key 要求存起來
  Then 助理說明外掛不能存金鑰，請到網頁的設定頁自己設定
  And 助理不複述、不轉送貼出的內容

Scenario: 改機器人不動自動下單（例 6）
  Given 機器人乙的自動下單開著
  When 使用者說「把乙的觸發間隔改成 15 分鐘」
  Then 乙的觸發間隔變成 15 分鐘
  And 乙的自動下單維持開著

Scenario: 建立機器人時不能順帶打開
  When 使用者說「建一台新的合約機器人，順便打開自動下單」
  Then 機器人建立成功，自動下單為關
  And 助理說明打開自動下單只能在網頁的機器人詳細頁自己做
```

## 4. Business Flow & Logic

- **Core Business Rules:**
  - 外掛讀到的自動下單狀態與幣安交易金鑰狀態，全是交易服務的原話；外掛不推算、不補值。
  - 外掛**沒有**存入、更換、移除金鑰，或打開、關掉自動下單這幾件事——不是擋下來，是能力清單裡根本沒有。
  - 建立與修改機器人**不帶**自動下單；就算助理填了，也不轉送給交易服務。交易服務在修改時本來就保留原本的開關。
  - 「有沒有設定幣安交易金鑰」是**另立一件只讀的事**，不併入「我是誰」：
    「我是誰」回答的是外掛授權代表哪個帳號，與交易設定無關；把兩件事併成一件，等於外掛要替一次詢問向交易服務問兩次並自己拼回覆，
    違反「一件事對應交易服務的一件事」。另立一件，助理也只在使用者問到幣安時才去讀。
  - 尚未設定時，可交易市場是空的、設定時刻沒有意義；助理只說「尚未設定」，不說出一個看起來像日期的值。
- **Edge Cases:**
  - 交易服務還沒有這個功能（舊版）：讀狀態那一件被拒絕或找不到，原話帶回；機器人回覆沒有自動下單那一格時，助理不臆測為開或關。
  - 連不到交易服務：照既有說法「連不到交易服務」。
  - 外掛授權失效：照既有說法請使用者到 /mcp 重新連線。

## 6. Non-Functional Requirements

- **Security:** 外掛不經手任何一段金鑰：沒有收金鑰的欄位，讀到的狀態也不含金鑰內容。助理被要求不複述、不轉送使用者貼出的金鑰。
- **Performance / Compatibility / Analytics:** N/A。

---

## 7. Dependencies & Risks

- **External Dependencies:** 交易服務同名切片（CodeMachine0121/go-trading#87）上線後，讀狀態那一件才有回覆；機器人回覆才帶自動下單。
- **Known Risks:** 助理仍可能在對話裡複述使用者貼出的金鑰——外掛只能透過說明約束它，無法技術上阻止；所以說明要明確、出現在伺服器說明與相關能力上。
