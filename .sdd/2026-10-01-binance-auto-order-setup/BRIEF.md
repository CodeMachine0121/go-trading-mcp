# 幣安自動下單設定（外掛）— Requirements Brief

## Goal

交易服務這一刀新增使用者自己的一組**幣安交易金鑰**，以及每台策略機器人上的**自動下單**開關（這一刀還不會真的下單）。
外掛的角色**只能讀**：讓使用者在 Claude Code 裡看得到哪台機器人開著自動下單、自己有沒有設定幣安交易金鑰，
但**不能**存金鑰、移除金鑰，也**不能**打開或關掉自動下單。

業務規則與拒絕一律以 `go-trading/.sdd/2026-10-01-binance-auto-order-setup/BRIEF.md` 為準。

## Requirements

### 一、讀得到的

- 查看或列出策略機器人（現貨與合約）時，回覆帶出這台機器人的**自動下單是開是關**。
- 使用者問起時，助理說得出他**有沒有**設定幣安交易金鑰，以及**可交易市場**（現貨／合約／兩者）。
- **不給任何一段金鑰內容**——連 API Key 的結尾也不給。

### 二、沒有的能力

- **沒有**存入、更換、移除幣安交易金鑰的能力。
- **沒有**打開或關掉自動下單的能力；建立或修改機器人的能力**也不能**順帶改動它。
- 理由：金鑰不該經過一段 AI 對話、留在對話紀錄裡；「讓機器人拿真錢下單」必須由人親手按。

### 三、代辦規矩

- 使用者要求設定金鑰或切換自動下單時，助理說明這件事只能在網頁的設定頁或機器人詳細頁自己做，
  **不要求使用者把金鑰貼進對話**；使用者主動貼了，也不轉送、不複述。
- 助理提到自動下單時要說清楚：**目前開著也還不會下單**，機器人仍只送 Telegram 通知。

## Examples (Specification by Example)
Each example lists **only** the data that affects the behavior — nothing more.

| # | Given (only relevant data) | When | Then |
|---|---|---|---|
| 1 (happy) | 合約機器人甲自動下單開著 | 使用者說「看一下我的機器人」 | 回覆列出甲並標出自動下單：開，補一句目前開著還不會下單 |
| 2 (happy) | 已設定金鑰，可交易：現貨 | 使用者問「我設定幣安了嗎」 | 回覆已設定、可交易市場：現貨；不給任何一段金鑰 |
| 3 (boundary) | 尚未設定金鑰 | 同上 | 回覆尚未設定，並指引到網頁設定頁 |
| 4 (exception) | — | 使用者說「幫我把甲的自動下單打開」 | 說明這件事只能在網頁上自己做，不送出任何改動 |
| 5 (exception) | — | 使用者在對話裡貼出一組 API Key 與 Secret Key 要求存起來 | 說明外掛不能存金鑰、請到網頁設定頁；不複述貼出的內容 |
| 6 (exception) | 機器人乙自動下單開著 | 使用者說「把乙的觸發間隔改成 15 分鐘」 | 只改觸發間隔；自動下單維持開著 |

## Out of Scope

- 任何寫入金鑰或切換自動下單的能力（包括「只能關、不能開」——本切片決定外掛完全不碰開關）。
- 下單相關的任何能力。

## Open Decisions

- 有沒有設定金鑰，要放在既有的「目前使用者」資訊裡回覆，還是另立一個只讀的能力。

## Context / Background

- 延續外掛「交易服務內建的行情對話助手刻意不開放」的同一個理由：某些決定不該由 AI 代為做出。
- 使用者曾考慮讓外掛「可以關、不能開」當緊急煞車，最後選擇只讀；緊急關掉在網頁上隨時做得到。
