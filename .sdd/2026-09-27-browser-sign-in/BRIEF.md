# 在瀏覽器登入外掛 — Requirements Brief

## Goal

今天使用者要把**電子郵件與密碼告訴助理**，由助理替他登入外掛；密碼因此會出現在對話裡，而且身分只存在某一台外掛的記憶裡，
那一台重啟或換一台，所有人都得重新登入。這一刀把登入整個搬離對話：使用者在 Claude Code 的外掛選單按「連線」，
瀏覽器打開交易服務的網站，他在網站上登入並按下**允許**，Claude Code 就拿到一份**外掛授權**，之後每一次代辦都帶著它。
外掛從此**不保管任何人的身分、不經手任何密碼**，只負責確認「這一次帶來的外掛授權是真的、而且是給這個外掛的」，
然後以那一份身分替使用者代辦。續用、換新都由 Claude Code 與交易服務（授權伺服器）自己處理。

## Requirements

**整個外掛都要先有外掛授權**

- 沒有帶外掛授權、或帶來的授權不是真的、已失效、或是發給別的服務的，外掛一律不接待，並指引 Claude Code 去哪裡取得授權
  （由交易服務負責發授權）。Claude Code 看到這個指引就會自己帶使用者走瀏覽器登入。
- 外掛要公開說明「我是誰、授權找誰拿」，讓 Claude Code 不必事先設定就找得到交易服務。
- 沒有任何能力可以在沒有外掛授權的情況下使用——連「列出會做的事」與「確認服務活著」都一樣。（外掛自己的健康檢查不在此限，那不是能力。）

**確認外掛授權**

- 每一份外掛授權都交給交易服務確認：它還有效、屬於一位還存在的使用者、而且**是發給這個外掛的**。三者缺一即不接待。
- 同一份授權短時間內重複出現時，不必每次都問交易服務：最多記住一分鐘，且絕不記得比授權本身的到期時刻更久。
- 問不到交易服務（交易服務暫時不在）時，外掛說的是「暫時連不到交易服務」，**不是**「請重新授權」——那不是使用者的錯，重新授權也不會好。這種結果不被記住。

**代辦時以使用者的身分進行**

- 每一件事都帶著使用者這一次帶來的外掛授權去問交易服務。
- 交易服務說「不認得這個身分」時，外掛回覆請使用者**到 Claude Code 的外掛選單重新連線**；不再自己換新、不再重試。
- 交易服務其他的拒絕（規則不通過、帳號尚未開通…）照舊原話帶回。

**拿掉的東西**

- 登入、登出、立即換新登入、建立使用者這四件能力拿掉（建立帳號與登入都在交易服務的網站上做）。
- 「請先提供電子郵件與密碼」的說明、每件能力後面「請先登入」的附註拿掉。
- 外掛記憶裡的身分保管、以及身分過期時自己換新與重試的機制拿掉。
- 「我是誰」與「改密碼」兩件能力保留。

**部署**

- 外掛不再有記在記憶裡的身分，可以同時跑不只一份；某一份重啟，使用者不必重新授權。只改說明文件。

## Examples (Specification by Example)

### Rule: 沒有有效外掛授權就不接待

| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 帶著有效、發給這個外掛的外掛授權 | 助理列出會做的事 | 照常列出 |
| 2 (exception) | 沒有帶任何授權 | 助理連上外掛 | 不接待，並指出授權說明在哪裡 |
| 3 (exception) | 授權已被交易服務判定失效 | 助理查 K 線 | 不接待，並指出授權說明在哪裡 |
| 4 (boundary) | 授權有效，但是發給**別的服務**的 | 助理查 K 線 | 不接待——不是給這個外掛的授權不算數 |
| 5 (boundary) | 授權有效，發給這個外掛，只是寫法多了結尾的斜線 | 助理查 K 線 | 照常接待——同一個對象的兩種寫法算同一個 |
| 6 (exception) | 交易服務暫時不在 | 助理帶著授權連上外掛 | 回「暫時連不到交易服務」，不是「請重新授權」 |

### Rule: 同一份授權的確認結果記一小段時間

| # | Given | When | Then |
|---|---|---|---|
| 7 (happy) | 同一份授權三十秒前確認過是有效的 | 助理再做一件事 | 不再問交易服務 |
| 8 (boundary) | 同一份授權六十秒前確認過 | 助理再做一件事 | 重新問交易服務 |
| 9 (boundary) | 授權二十秒後到期，剛確認過 | 二十五秒後助理再做一件事 | 重新問交易服務（不記得比到期更久） |
| 10 (exception) | 上一次問的時候交易服務不在 | 助理再做一件事 | 重新問，不沿用「不在」的結果 |

### Rule: 公開說明授權找誰拿

| # | Given | When | Then |
|---|---|---|---|
| 11 (happy) | — | Claude Code 查外掛的授權說明 | 說出這個外掛的正式位址，以及授權要向交易服務的公開位址拿 |
| 12 (boundary) | — | Claude Code 用帶外掛路徑的那一個位址查 | 回同一份說明 |

### Rule: 代辦時以使用者的身分進行

| # | Given | When | Then |
|---|---|---|---|
| 13 (happy) | 使用者已授權 | 助理把一個標的加進觀察清單 | 帶著他的授權去問，照常加進去 |
| 14 (happy) | 使用者已授權 | 助理查一段 K 線 | 一樣帶著他的授權去問 |
| 15 (exception) | 交易服務說不認得這份身分 | 助理做任何一件事 | 回「請到 Claude Code 的外掛選單重新連線」，不重試 |
| 16 (exception) | 帳號還沒開通 | 助理建立一支策略腳本 | 交易服務的原話帶回 |

### Rule: 拿掉的能力不再出現

| # | Given | When | Then |
|---|---|---|---|
| 17 (happy) | — | 助理列出會做的事 | 沒有登入、登出、換新登入、建立使用者；有「我是誰」與「改密碼」 |
| 18 (boundary) | — | 助理讀外掛的使用說明 | 不再請它向使用者要電子郵件與密碼 |

## Out of Scope

- 交易服務的授權伺服器本身（發授權、登入與允許頁面）——在交易服務與網站那兩刀做。
- 部署設定的實際修改。
- 權限範圍的細分：一份外掛授權即是完整代辦權。

## Open Decisions

- 無。以下是代替提問、依合約與常規做的決定：
  - **每一件事都帶身分**：整個外掛都已要求授權，不再區分「要不要身分」的能力；這也是合約所說的「代辦時轉送同一份授權」。
  - **問不到交易服務不算授權失效**：沿用既有「連不到交易服務」與「請重新登入」絕不共用一句話的規則。
  - **記住上限一分鐘**：合約給定；失敗的結果不記。
  - **連線本身照舊**：外掛與 Claude Code 之間的一段往來仍在，但不再與身分綁在一起；落到另一份外掛時，Claude Code 重新開一段往來即可，不必重新授權。
  - **外掛自己的公開位址由設定給**：正式環境前面的轉送會改寫來源資訊，從請求推算會算錯。

## Context / Background

跨三個專案的合約：外掛是受保護的資源、交易服務是授權伺服器（外掛授權）、網站提供登入與允許頁面。
此外掛必須在**交易服務的授權伺服器上線並完成部署設定之後**才部署，否則沒有人拿得到外掛授權。
