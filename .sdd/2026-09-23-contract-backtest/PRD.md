# Product Requirements Document (PRD)

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh

---

## 1. Background & Goal

- **Problem Statement:** 交易服務已經重演得了逐倉的合約帳戶，交易策略也說得出行情種類與合約交易模式，
  但外掛的能力清單不知道，而且它的說明還在告訴助理「這個服務只重演現貨、做不了空」，會讓助理把使用者擋回去。
- **Expected Outcome:**
  - 助理能**重演一支合約策略腳本**與**重演一份合約交易策略**，說得出槓桿、交易模式（只有腳本那一件）、滑點。
  - 助理能**建立與修改合約交易策略**，說得出行情種類與交易模式。
  - 說明教得會助理讀合約成績單，也把「只重演現貨」那句話改成指向合約重演。
- **Out of Scope:** 合約的策略機器人；外掛自己驗證任何合約參數；裁掉回應內容。

---

## 2. User Personas

- **Primary Role:** 透過助理操作交易服務的使用者；實際讀說明、填格子的是助理。
- **Usage Context:** 對話中請助理「用五倍槓桿在 BTC 永續上重演這支腳本」「幫我拼一份只做空的合約交易策略再重演」。

## 3. User Stories & Acceptance Criteria

### US-01 — 重演一支合約策略腳本 [P0]

**As a** 使用者, **I want** 助理在合約帳戶上重演一支合約策略腳本, **so that** 我看得到槓桿、做空、強平、資金費率之下的成績。

```gherkin
Scenario: 帶著合約的條件重演
  Given 一支吃合約行情的策略腳本
  When 助理以槓桿 5、交易模式只做空、滑點 0.05 重演 BTCUSDT 永續
  Then 交易服務的合約重演收到槓桿 5、交易模式只做空、滑點 0.05，以及合約標的與期間
  And 回來的合約成績單與交易明細原樣轉達

Scenario: 沒填的合約條件不送出
  When 助理重演時沒填槓桿、交易模式、滑點
  Then 那三格都不出現在送出的內容裡，由交易服務照它自己的預設

Scenario: 必填的格子沒填
  When 助理重演時沒填合約標的
  Then 送出前被擋下，並說出缺的是合約標的那一格

Scenario: 交易服務拒絕
  Given 交易服務以「吃的是 K 線」拒絕
  When 助理重演
  Then 拒絕的原話原樣帶回

Scenario: 說明寫出會被拒絕的情況與合約帳戶怎麼算
  When 助理讀這件能力的說明
  Then 讀得到：吃 K 線的腳本、沒有交易規格的標的、槓桿小於一或超過上限、現貨不是合約的交易模式、另外指定維持保證金率都會被拒絕
  And 讀得到：逐倉最多賠光那一注保證金、強平看標記價格、資金費率一律計入、分級用的是今天那一組
```

### US-02 — 重演一份合約交易策略 [P0]

**As a** 使用者, **I want** 助理重演一份合約交易策略, **so that** 我在上線前看得到這整套判斷在合約帳戶上的成績。

```gherkin
Scenario: 指名交易策略重演
  When 助理以槓桿 3 重演第 11 份交易策略
  Then 送到第 11 份交易策略的合約重演，帶槓桿 3

Scenario: 沒有交易模式可以填
  When 助理看這件能力有哪些格子
  Then 沒有交易模式那一格
  And 說明寫出交易模式由那份交易策略自己決定
```

### US-03 — 拼一份合約交易策略 [P0]

**As a** 使用者, **I want** 助理建立與修改合約交易策略, **so that** 交易策略記著它吃合約行情與它的交易模式。

```gherkin
Scenario: 建立時說出行情種類與交易模式
  When 助理建立一份交易策略，行情種類合約行情、交易模式只做多
  Then 兩格都送出

Scenario: 修改時不提行情種類
  When 助理修改一份交易策略且沒填行情種類
  Then 那一格不送出，交易服務保留原本的

Scenario: 說明寫出兩格的規則
  When 助理讀建立或修改交易策略的說明
  Then 讀得到：行情種類建立後不得更換、每個信號來源要吃同一種行情
  And 讀得到：只有合約交易策略有交易模式，K 線交易策略給了會被拒絕
```

### US-04 — 說法改對 [P0]

**As a** 使用者, **I want** 助理不再說合約的事做不到, **so that** 我要放空或開槓桿時被帶去正確的能力。

```gherkin
Scenario: 現貨重演指向合約重演
  When 助理讀現貨重演兩件的說明
  Then 讀得到「只重演現貨」與要改用合約重演
  And 讀不到「這個服務目前不做」

Scenario: 現貨重演仍然沒有合約的格子
  When 助理看現貨重演兩件有哪些格子
  Then 沒有交易模式、槓桿、滑點、維持保證金率

Scenario: 合約算式的說明只說機器人還不行
  When 助理讀合約算式的說明
  Then 讀得到可以拿去合約重演與合約交易策略
  And 讀得到策略機器人目前只跑 K 線

Scenario: 清單涵蓋新的兩件
  When 列出會做的事
  Then 多了合約重演一支腳本與合約重演一份交易策略，兩件都需要身分
```

## 4. Business Flow & Logic

- 兩件合約重演與既有能力走同一條轉達路徑：必填格子先擋、填了的才送出、拒絕原話帶回。
- 合約重演共用的條件（本金、倉位大小、出場價位、交易成本、槓桿、滑點）**只寫一份**，兩件都讀它。
- 合約帳戶怎麼算的說法**只寫一份**，兩件都讀它。
