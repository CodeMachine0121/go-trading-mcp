# Product Requirements Document (PRD) — 交易方向從交易策略搬到機器人與回測（外掛）

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering（與交易服務同時上線）

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 交易服務把合約交易模式從交易策略身上拿掉：交易策略只回答買入、賣出、持有；合約機器人在自己身上選**交易方向**，
  合約交易策略的回測由送出的人說這一次的交易方向；每台機器人另有**買入、賣出、持有**三個通知開關。
  外掛仍告訴助理「合約交易策略記著自己的交易模式、回測它時不能給、要換就改交易策略」，並在建立或修改交易策略時提供交易模式這一項——
  升級後助理照這樣做會被整份拒絕；助理也不知道可以替機器人選方向、設定通知，更不知道一台開著自動下單的機器人改不了方向。
- **Expected Outcome:**
  - 建立或修改交易策略時助理不再說交易模式；讀交易策略時不期待看到它。
  - 助理能替合約機器人選交易方向（做多、做空或兩者），說得出每種方向下買入、賣出的意思。
  - 助理能替機器人設定三種結論通知，說得清關掉通知不影響信號與自動下單。
  - 助理能在回測合約交易策略時說交易方向。
  - 助理知道外掛改不了開著自動下單的機器人的方向，會請使用者到網頁先關掉自動下單。
- **Out of Scope:**
  - 外掛自己檢查方向、通知或改方向的限制（交易服務是規則的來源；外掛原樣轉送、拒絕照原話轉述）。
  - 打開或關掉自動下單（仍只能在網頁上）；逐種結論決定自動下單。
  - 實盤與回測比對的方向（交易服務自己從交易推得）；標的篩選設定與直接回測合約腳本的方向（不變）。

---

## 2. User Personas

- **Primary Role(s):** 助理（透過外掛代使用者操作）；交易策略與機器人的擁有者（對助理下指令的人）。
- **Usage Context:** 使用者在對話裡請助理建立或調整交易策略、合約機器人、通知，並回測某個方向的成績。

---

## 3. User Stories & Acceptance Criteria

### US-01 — [priority: P0] 交易策略不再帶交易方向
**As a** 助理, **I want** 知道交易策略不再有交易模式, **so that** 我建立或修改它時不會被整份拒絕。

```gherkin
Scenario: 建立合約交易策略不提交易方向
  Given 使用者要建一份吃合約行情的交易策略，沒提方向
  When 助理建立它
  Then 送給交易服務的內容沒有交易模式
  And 建立交易策略的能力沒有交易模式這一項可填

Scenario: 使用者要求交易策略只做多
  Given 使用者說「這份交易策略只做多」
  When 助理讀建立交易策略能力的說明
  Then 說明告訴助理交易方向改由機器人與回測決定，要設在機器人的交易方向或回測的交易模式上

Scenario: 修改時仍送交易模式被拒
  Given 助理修改一份交易策略時送了「多空反手」
  When 交易服務拒絕並說明交易方向已改由機器人與回測決定
  Then 外掛把拒絕的原話帶回給助理
  And 修改交易策略的能力說明不再寫「不給就是保留原本的交易模式」

Scenario: 讀交易策略看不到交易模式
  When 助理讀查看交易策略能力的說明
  Then 說明不再說合約交易策略帶著交易模式
  And 說明告訴助理同一份交易策略可以同時養做多與做空的機器人
```

### US-02 — [priority: P0] 合約機器人的交易方向
**As a** 助理, **I want** 替合約機器人選交易方向, **so that** 機器人照使用者要的方向解讀交易策略的結論。

```gherkin
Scenario: 建立時選做多
  Given 合約機器人，使用者說「只做多」
  When 助理建立它
  Then 送給交易服務的內容帶著交易方向「做多」

Scenario: 建立時沒說方向
  Given 合約機器人，使用者沒說方向
  When 助理建立它
  Then 送給交易服務的內容沒有交易方向
  And 說明告訴助理這時方向是做多加做空（多空反手）

Scenario: 一個方向都沒選
  Given 助理送出空的交易方向清單
  When 建立機器人
  Then 交易服務拒絕並說至少要選一個，外掛把原話帶回
  And 說明預先寫出至少要選一個

Scenario: 現貨機器人送來方向
  Given 現貨機器人，助理送了做多
  When 建立
  Then 交易服務拒絕，說明預先寫出現貨機器人沒有交易方向

Scenario: 同一份交易策略兩台方向不同
  Given 同一份交易策略，A 機器人方向「做多」、B 機器人方向「做空」
  When 使用者問同一個賣出結論兩台各做什麼
  Then 說明讓助理說出 A 平多、B 做空（只做多：買入做多、賣出平多；只做空：賣出做空、買入平空；兩者：多空反手）

Scenario: 只改名字時方向保留
  Given 已停止的合約機器人，方向「做空」
  When 助理只改名字、不送交易方向
  Then 修改機器人能力的說明告訴助理沒送方向即保留原本的「做空」

Scenario: 讀機器人看得到方向
  When 助理讀查看、列出或啟動機器人能力的說明
  Then 說明告訴助理合約機器人的回覆帶著交易方向，現貨機器人沒有
```

### US-03 — [priority: P0] 改交易方向的安全限制
**As a** 助理, **I want** 知道什麼時候改不了交易方向, **so that** 我不會反覆重送，也不會假裝能替使用者關掉自動下單。

```gherkin
Scenario: 安全時改方向
  Given 已停止、自動下單關著、沒有機器人持倉的合約機器人，方向「做多」
  When 助理把方向改成「做空」
  Then 送給交易服務的內容帶著交易方向「做空」

Scenario: 自動下單開著時改方向
  Given 已停止、自動下單開著的合約機器人
  When 助理改交易方向而被交易服務拒絕（自動下單開著）
  Then 說明告訴助理：外掛無法關掉自動下單，請使用者到網頁上那台機器人的詳細頁先關掉，再回來改方向
  And 不要重送同一份

Scenario: 監聽標的還有機器人持倉
  Given 已停止、自動下單關著，BTCUSDT 還有機器人持倉
  When 助理改交易方向而被拒絕
  Then 說明告訴助理照原話說 BTCUSDT 還有持倉，要先讓它空手

Scenario: 監聽標的還有沒做完的自動下單
  Given 已停止，BTCUSDT 還有沒做完的自動下單委託
  When 助理改交易方向而被拒絕
  Then 說明告訴助理要等它做完再改

Scenario: 方向不變只改間隔
  Given 已停止、自動下單開著的合約機器人
  When 助理只改觸發間隔、不送交易方向
  Then 說明告訴助理方向沒變就不受自動下單限制，修改照常

Scenario: 執行中改方向或通知
  Given 執行中的機器人
  When 助理改方向或通知
  Then 說明照舊寫只有已停止的機器人改得動
```

### US-04 — [priority: P1] 每種結論的通知
**As a** 助理, **I want** 替機器人設定買入、賣出、持有通知, **so that** 使用者只在關心的結論被打擾。

```gherkin
Scenario: 關掉買入通知
  Given 已停止的機器人，使用者說「買入不要通知我」
  When 助理修改它
  Then 送給交易服務的通知只帶買入「關」
  And 說明告訴助理沒說的賣出、持有通知維持原本的

Scenario: 建立時沒提通知
  When 助理建立機器人而沒送通知
  Then 說明告訴助理這時買入開、賣出開、持有關

Scenario: 關掉通知仍會下單
  Given 買入通知關著、自動下單開著
  When 使用者問「這樣還會下單嗎」
  Then 說明讓助理說會：只是不寄那一則訊息，信號照樣算數、照樣擋重複、自動下單照樣行動

Scenario: 回到持有
  Given 持有通知開著，監聽標的前一個結論是買入
  When 這一輪結論持有
  Then 說明讓助理認得「回到持有」那一則：沒有建議部位、不觸發自動下單

Scenario: 連續持有
  Given 持有通知開著，監聽標的已經回到持有
  When 又一輪結論持有
  Then 說明告訴助理不會再寄

Scenario: 三個通知都關
  Given 三個通知都關著
  When 使用者問「怎麼都沒訊息」
  Then 說明讓助理說機器人照跑，只是輪次訊息都不寄；已啟動、已停止照寄

Scenario: 讀機器人看得到通知
  When 助理讀查看或列出機器人能力的說明
  Then 說明告訴助理每台機器人帶著三個通知開關
```

### US-05 — [priority: P0] 合約交易策略回測的交易方向
**As a** 助理, **I want** 回測合約交易策略時說交易方向, **so that** 同一份交易策略能分別看做多與做空的成績。

```gherkin
Scenario: 回測只做空
  Given 合約交易策略，使用者說「回測只做空」
  When 助理送出回測
  Then 送給交易服務的內容帶著交易模式「只做空」
  And 說明告訴助理成績單記著這一次的方向

Scenario: 回測沒說方向
  Given 合約交易策略，使用者沒說方向
  When 助理送出回測
  Then 送給交易服務的內容沒有交易模式
  And 說明告訴助理這時照多空反手重演

Scenario: 現貨交易策略回測說方向
  Given 現貨交易策略，使用者說「回測只做多」
  When 助理讀現貨回測能力
  Then 現貨回測能力沒有交易模式可填，說明告訴助理要做空改用合約重演

Scenario: 標的篩選設定不受影響
  When 助理建立或修改篩選設定
  Then 篩選設定照舊有自己的交易模式可填
```

## 4. Business Flow & Logic

- **Core Business Rules:**
  - 交易策略沒有交易模式；送來即整份被拒。
  - 交易方向（合約機器人）：做多、做空，至少一個。只有做多＝買入做多、賣出平多；只有做空＝賣出做空、買入平空；兩者＝多空反手。建立不說＝兩者，修改不說＝保留。現貨機器人沒有。
  - 改交易方向：須已停止 → 自動下單須關著 → 每個監聽標的沒有機器人持倉、沒有未完成的自動下單。方向沒變不受後兩項限制。開關自動下單只能在網頁上，所以外掛改不了真錢機器人的方向。
  - 結論通知：三個開關，建立不說＝買入開、賣出開、持有關；修改時沒說的保留。關掉買入或賣出只是不寄訊息。持有通知只在回到持有時寄一則，沒有建議部位、不下單。三個都關機器人照跑。
  - 合約交易策略回測：交易模式由那一次說，不說＝多空反手。現貨回測沒有。
  - 外掛原樣轉送、不檢查；拒絕照原話帶回。
- **Edge Cases:**
  - 使用者要求外掛關掉自動下單好改方向 → 說明外掛做不到，請他到網頁上自己關。
  - 使用者要求交易策略「只做多」 → 說明方向在機器人或回測上。

## 6. Non-Functional Requirements

- **Compatibility:** 交易服務不向下相容（交易策略送交易模式即拒），外掛與交易服務同時上線。
- **Security:** 開關自動下單仍只能在網頁上；外掛不帶、不轉送自動下單開關，因此改不了真錢機器人的方向。

---

## 7. Dependencies & Risks

- **External Dependencies:** 交易服務「交易方向從交易策略搬到機器人與回測」切片。
- **Known Risks:**
  - 助理照舊在交易策略上說交易模式 → 移除那一項並在說明寫明去處。
  - 助理把「關掉通知」講成「機器人不會下單」 → 說明寫明通知只管訊息。
