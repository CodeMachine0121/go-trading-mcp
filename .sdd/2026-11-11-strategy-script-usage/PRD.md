# Product Requirements Document (PRD) — 策略腳本的用途（外掛）

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering（與交易服務同時上線）

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 交易服務讓每一支策略腳本標明**用途**（圖表用／計算用）：交易策略的信號來源、標的篩選設定、直接回測只接受計算用；
  網頁圖表的指標選單只列圖表用；改寫腳本內容時不能帶用途，另有一個獨立的**切換用途**動作。
  外掛目前不知道用途：建立腳本時說不了、讀腳本時看不懂、沒有切換用途的能力，助理也不知道圖表用的腳本會被交易策略拒絕。
- **Expected Outcome:**
  - 助理建立腳本時能說用途（不說即計算用），改寫時不帶用途。
  - 助理能切換自己的腳本（含市集副本）的用途，被拒時照原話說出是哪幾份在用。
  - 助理在組交易策略、篩選設定、直接回測時只挑計算用的腳本。
  - 助理讀腳本、列出腳本、瀏覽市集時看得懂用途，並能解釋「圖表上找不到我的指標」。
- **Out of Scope:**
  - 外掛自己檢查用途（交易服務是規則的來源）。
  - 依指標值種類自動推測用途、新的用途種類、圖表指標選單本身。

---

## 2. User Personas

- **Primary Role(s):** 助理（透過外掛代使用者操作）；策略腳本擁有者、從市集加入副本的使用者。
- **Usage Context:** 使用者在對話裡請助理寫腳本、整理腳本、組交易策略或回測，或問為什麼圖表上看不到某支腳本。

---

## 3. User Stories & Acceptance Criteria

### US-01 — [priority: P0] 建立時說用途、改寫時不帶
**As a** 助理, **I want** 建立腳本時說它的用途, **so that** 它出現在對的地方。

```gherkin
Scenario: 建立圖表用腳本
  Given 使用者說「做一支畫在圖上看的均線」
  When 助理建立它
  Then 送給交易服務的內容帶著用途「圖表用」

Scenario: 建立時沒說用途
  Given 使用者沒說用途
  When 助理建立它
  Then 送給交易服務的內容沒有用途
  And 說明告訴助理這時是計算用

Scenario: 用途不在兩種之內
  Given 助理送了用途「回測用」
  When 建立
  Then 交易服務拒絕，外掛把原話帶回
  And 說明預先寫出用途只能是圖表用或計算用

Scenario: 改寫內容不帶用途
  When 助理改寫一支自己的腳本
  Then 改寫腳本的能力沒有用途這一項可填，送出的內容沒有用途
  And 說明告訴助理改寫不會動到用途，要改用途請用切換用途
```

### US-02 — [priority: P0] 切換用途
**As a** 助理, **I want** 切換使用者腳本的用途, **so that** 使用者能整理自己的腳本，包括市集副本。

```gherkin
Scenario: 沒人在用的腳本切成圖表用
  Given 一支計算用、沒人在用的腳本
  When 助理把它切成圖表用
  Then 外掛向交易服務送出切換，內容只有用途「圖表用」
  And 帶回切換後的腳本，用途為圖表用

Scenario: 交易策略在用時不能切成圖表用
  Given 一支計算用的腳本，交易策略「4H 趨勢」在用
  When 助理把它切成圖表用而被拒絕
  Then 外掛把說出「4H 趨勢」的原話帶回
  And 說明告訴助理請使用者先把它從那些交易策略換掉，不要重送

Scenario: 篩選設定在用時不能切成圖表用
  Given 一支計算用的腳本，篩選設定「新幣」在用
  When 助理把它切成圖表用而被拒絕
  Then 外掛把說出「新幣」的原話帶回

Scenario: 圖表用切回計算用
  Given 一支圖表用的腳本
  When 助理把它切成計算用
  Then 說明告訴助理切成計算用沒有限制

Scenario: 切成原本的用途
  Given 一支計算用的腳本
  When 助理把它切成計算用
  Then 說明告訴助理這不算失敗，什麼也不變

Scenario: 市集副本也能切換
  Given 一支計算用、沒人在用的市集副本
  When 助理把它切成圖表用
  Then 說明告訴助理副本也能切換，算式仍然看不到也改不了

Scenario: 別人的腳本
  Given 一支屬於別人的腳本
  When 助理要切換它
  Then 說明告訴助理會被拒絕，說法與找不到相同
```

### US-03 — [priority: P0] 計算的地方只接受計算用
**As a** 助理, **I want** 知道哪裡只接受計算用, **so that** 我挑對腳本、被拒時知道怎麼辦。

```gherkin
Scenario: 圖表用的腳本當信號來源
  Given 交易策略的信號來源指名一支圖表用的腳本
  When 助理讀建立或修改交易策略能力的說明
  Then 說明告訴助理只有計算用的腳本能當信號來源，圖表用的會被拒絕，可以先切成計算用

Scenario: 篩選設定指名圖表用的腳本
  When 助理讀建立或修改篩選設定能力的說明
  Then 說明告訴助理篩選只接受計算用的腳本

Scenario: 直接回測圖表用的腳本
  When 助理讀兩件直接回測策略腳本能力的說明
  Then 說明告訴助理指名的腳本必須是計算用
  And 自己帶一段還沒存的算式不受用途影響

Scenario: 試算不受用途影響
  When 助理讀兩件算指標能力的說明
  Then 說明告訴助理兩種用途的腳本都能算
```

### US-04 — [priority: P1] 看得懂用途
**As a** 助理, **I want** 讀腳本時看到用途, **so that** 我能回答腳本放在哪裡、為什麼圖表上找不到。

```gherkin
Scenario: 查看與列出腳本
  When 助理讀查看與列出策略腳本能力的說明
  Then 說明告訴助理每一支都帶著用途（圖表用／計算用）

Scenario: 市集帶著用途
  When 助理讀瀏覽市集與加入能力的說明
  Then 說明告訴助理市集上的腳本帶著用途，加入的副本帶著加入當下的用途，之後發佈者切換不影響副本

Scenario: 圖表上找不到我的指標
  Given 使用者說「圖表上找不到我寫的指標」，那支是計算用、沒人在用
  When 助理讀切換用途或列出腳本能力的說明
  Then 說明告訴助理網頁圖表的指標選單只列圖表用，升級前既有的腳本都是計算用，徵得同意後可以切成圖表用
```

## 4. Business Flow & Logic

- **Core Business Rules:**
  - 用途二選一：圖表用、計算用；建立時不說即計算用；改寫內容不能帶用途。
  - 切換用途：自己的腳本與市集副本都可以；切成圖表用時有交易策略或篩選設定在用即被拒並說出是哪幾份；切成計算用無限制；切成原本的不變；別人的同找不到。
  - 只接受計算用：交易策略信號來源、標的篩選設定、直接回測指名的腳本。自帶算式、單純算一次指標不受影響。
  - 網頁圖表的指標選單只列圖表用；既有腳本升級後都是計算用。
  - 外掛原樣轉送、不檢查；拒絕照原話帶回。
- **Edge Cases:**
  - 使用者要把正在被交易策略用的腳本切成圖表用 → 說出是哪幾份在用，請他先換掉，不重送。

## 6. Non-Functional Requirements

- **Compatibility:** 交易服務改寫腳本時送用途即拒，外掛改寫能力不得帶用途；與交易服務同時上線。
- **Security:** 不變——一切以使用者授權給外掛的帳號進行。

---

## 7. Dependencies & Risks

- **External Dependencies:** 交易服務「策略腳本的用途」切片（含新的切換用途動作）。
- **Known Risks:** 升級後畫線用的腳本暫時不在圖表選單——助理要能解釋並協助切換。
