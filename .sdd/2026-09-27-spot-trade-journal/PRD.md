# Product Requirements Document (PRD) — 助理代記現貨交易日誌

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh
**Stakeholders:** 交易服務（`go-trading` 同名切片，業務規則的唯一來源）、操作台（`go-trading-frontend` 同名切片）

---

## 1. Background & Goal

- **Problem Statement:** 交易服務新增了一本和合約分開的**現貨交易日誌**（加密貨幣現貨與台股），並把合約日誌的用語改成開倉、加倉、減倉、平倉。
  外掛今天只認得合約日誌：使用者說「剛買了 2330 一張」，助理只能硬塞進合約日誌或回答做不到；合約日誌能力的說明也還在說「成交」「成交價」，
  與交易服務的新用語不一致。
- **Expected Outcome:**
  - 使用者用說的就能記一筆現貨交易、加買進或賣出、修正或刪除持有中的買賣、改計畫、加附註、寫檢討、設定型態標籤、查交易、看現貨統計與現貨實盤 vs 回測、刪除現貨交易。
  - 助理知道現貨只有先買後賣、沒有槓桿；手續費沒說就是 0 並提醒台股證交稅要併入；台股以整數股計、「一張」是 1,000 股；現貨與合約都有的代號先問是哪一本。
  - 合約日誌能力的說明改用開倉、加倉、減倉、平倉與開倉價、平倉價，不再出現「成交」「成交價」；合約能力的行為不變。
  - 每一件都以授權給外掛的那位使用者身分進行；拒絕原話帶回；算不出的數字不說成 0；外掛不算任何一個數字。
- **Out of Scope:**
  - 從機器人連結預填（操作台的事）。
  - 現貨手續費率設定、幣別換算、現貨與合約合併的統計。
  - 外掛自己檢查任何日誌規則或計算任何損益與統計。

---

## 2. User Personas

- **Primary Role:** 代使用者操作交易服務的助理（使用者本人透過它說話）；使用者同時交易永續合約、加密貨幣現貨與台股。
- **Usage Context:**
  - 台股盤中或收盤後在 Claude Code 裡口述：「剛買了 2330 一張，1,050」。
  - 加密現貨買賣後口述：「0.05 顆 BTC 現貨，97,900 買的」。
  - 週末說「看這個月現貨績效」「2330 那筆寫檢討」。

---

## 3. User Stories & Acceptance Criteria

以下若無特別說明：使用者帶著有效的外掛授權；使用者的時區為台北（UTC+8）；2330 是交易服務認得的台股標的、BTCUSDT 同時是加密貨幣現貨標的與合約標的。

### US-01 — 用說的記一筆現貨交易 [P0]
**As a** 使用者, **I want** 口述一筆剛買的現貨就記進現貨日誌, **so that** 我不必另開操作台填表。

```gherkin
Scenario: 口述一張台股
  When 使用者說「剛買了 2330 一張，1,050」
  Then 交易服務建立一筆持有中的現貨交易：2330、買進 1,000 股、價格 1,050
  And 助理回覆這筆交易的編號，並說出「一張換算為 1,000 股」請使用者確認

Scenario: 口述加密貨幣現貨
  When 使用者說「現貨買了 0.05 顆 BTCUSDT，97,900」
  Then 交易服務建立一筆持有中的現貨交易：BTCUSDT、買進 0.05、價格 97,900

Scenario: 現貨沒有做空
  When 使用者說「現貨做空 ETH」
  Then 助理說明現貨只有先買後賣，不送出任何紀錄

Scenario: 現貨沒有槓桿
  When 使用者說「2330 現貨 3 倍」
  Then 助理說明現貨沒有槓桿，不送出任何紀錄

Scenario: 現貨與合約都有的代號先問
  When 使用者說「記一筆 BTCUSDT 買進 97,900」
  Then 助理先問這是現貨還是合約，得到回答前不送出

Scenario: 只貼機器人訊息不當成成交
  Given 使用者只貼上一則現貨機器人訊息（參考價 1,050），沒說實際價格
  When 使用者要求「幫我記一筆」
  Then 助理先問實際買進價，不拿參考價充當

Scenario: 同一標的已有持有中
  Given 使用者已有 2330 持有中的 #41
  When 使用者說「再記一筆 2330，1,060 買 500 股」
  Then 交易服務拒絕新增，助理原話帶回並建議改成在 #41 加一筆買進

Scenario: 沒說時間以現在為準
  Given 現在是台北時間 09-27 10:15
  When 使用者說「剛買了 2330 一張，1,050」，沒說時間
  Then 這筆買進以現在的時刻記下，助理回覆「時間記為 09-27 10:15（台北時間）」請使用者確認
```

### US-02 — 加買進、賣出與修正 [P0]
**As a** 使用者, **I want** 加碼、分批賣出都用說的記, **so that** 日誌和我的持股一致。

```gherkin
Scenario: 分批賣出
  Given #41 持有 1,000 股
  When 使用者說「#41 賣 400 股，1,100」
  Then #41 仍持有中，剩 600 股

Scenario: 全部賣出即平倉
  Given #41 持有 600 股
  When 使用者說「#41 剩下的 1,120 全賣」
  Then #41 變成已平倉，助理回覆淨損益與報酬率，並提醒可以寫檢討

Scenario: 賣出超過持有
  Given #41 持有 600 股
  When 使用者說「#41 賣 800 股」
  Then 交易服務拒絕，助理原話帶回「賣出超過持有」

Scenario: 台股必須整數股
  When 使用者說「2330 買 1,000.5 股」
  Then 助理說明台股以股計、必須是整數，請使用者更正

Scenario: 沒說手續費就是 0
  When 使用者記一筆 2330 賣出、沒提手續費
  Then 這筆手續費記為 0
  And 助理提醒台股賣出的證交稅要併入手續費，需要時可以修正

Scenario: 說了含稅手續費就照填
  When 使用者說「#41 賣 600 股 1,120，手續費含稅 1,983」
  Then 這筆手續費為 1,983

Scenario: 修正持有中的一筆買賣
  Given #41 持有中，一筆買進誤記為 1,005
  When 使用者說「那筆買進其實是 1,050」
  Then 助理先讀出那一筆，只改價格、其餘原樣帶上後修正

Scenario: 平倉後不能修正買賣
  Given #41 已平倉
  When 使用者要求修正其中一筆
  Then 交易服務拒絕，助理原話帶回並建議加附註或刪除整筆重記
```

### US-03 — 計畫、附註與檢討 [P0]
**As a** 使用者, **I want** 為現貨交易寫計畫與檢討, **so that** 我看得出自己在現貨上反覆犯的錯。

```gherkin
Scenario: 止損必須低於買進價
  Given #41 第一筆買進 1,050
  When 使用者說「#41 止損設 1,080」
  Then 交易服務拒絕，助理原話帶回「止損必須低於買進價」

Scenario: 只改一項計畫也不清掉其他項
  Given #41 的計畫有止損 1,000、止盈 1,150、理由「突破前高」
  When 使用者說「#41 止盈改 1,200」
  Then 助理先讀出現在的計畫，只改止盈、其餘原樣帶上

Scenario: 平倉後計畫鎖定
  Given #41 已平倉
  When 使用者說「把 #41 的止損改成 990」
  Then 交易服務拒絕，助理原話帶回並建議改成加附註

Scenario: 平倉後寫檢討
  Given #41 已平倉
  When 使用者口述檢討，執行評分 4、標「追價進場」
  Then #41 變成已檢討，貼著共用的失誤標籤「追價進場」
```

### US-04 — 查現貨交易、看統計與實盤 vs 回測 [P0]
**As a** 使用者, **I want** 問現貨交易與績效, **so that** 我知道台股與加密現貨各做得怎樣。

```gherkin
Scenario: 看現貨統計依市場分組
  Given 近 30 天台股與加密現貨都有已平倉交易
  When 使用者說「看這個月現貨績效」
  Then 助理回覆台股與加密貨幣兩組分開的統計，金額不跨幣別加總

Scenario: 平均 R 以有止損的筆數計
  Given 期間內只有 3 筆現貨交易有計畫止損
  When 使用者看現貨統計
  Then 助理說出平均 R 以 3 筆計

Scenario: 期間內沒有平倉
  Given 最近 7 天沒有現貨交易平倉
  When 使用者看最近 7 天的現貨統計
  Then 助理回覆這段期間沒有已平倉交易，勝率不適用而不是 0%

Scenario: 查看持有中的現貨交易
  Given #41 持有中
  When 使用者查看 #41
  Then 助理帶回浮動損益（估算）與報酬率，不提資金費用與強平價

Scenario: 現貨實盤 vs 回測
  Given 一份 K 線交易策略有 2330 的已平倉實單
  When 使用者要看它的實盤 vs 回測
  Then 助理帶回並排的平倉筆數與勝率，並說明重演不計成本

Scenario: 列出現貨交易可依市場篩選
  When 使用者說「列出我的台股交易」
  Then 助理只列出市場為台股的現貨交易，並說出總數
```

### US-05 — 合約日誌改用開倉／平倉的說法 [P0]
**As a** 使用者, **I want** 助理用合約的說法稱呼合約紀錄, **so that** 和交易服務、操作台的用語一致。

```gherkin
Scenario: 加倉
  Given 合約交易 #27 持倉中
  When 使用者說「#27 加倉 0.02 @ 98,100」
  Then 在 #27 加一筆開倉方向的紀錄，助理回覆以「加倉」「開倉價」稱呼

Scenario: 減倉與平倉
  Given #27 持倉 0.051
  When 使用者說「#27 平掉 0.02 @ 100,000」
  Then 助理稱這一筆為「減倉」、價格為「平倉價」

Scenario: 合約能力的說明不再出現成交
  When 助理讀合約日誌能力的說明
  Then 說明裡沒有「成交」「成交價」字樣，改為開倉、加倉、減倉、平倉與開倉價、平倉價
```

### US-06 — 刪除現貨交易 [P1]
**As a** 使用者, **I want** 刪掉記錯的現貨交易, **so that** 日誌保持乾淨。

```gherkin
Scenario: 確認後刪除
  Given 使用者說「刪掉剛剛那筆 2330」且確認是 #41
  When 助理送出刪除
  Then #41 連同買賣、附註、檢討一併刪除

Scenario: 指的不只一筆先問
  Given 使用者有兩筆 2330 現貨交易
  When 使用者說「刪掉 2330 那筆」
  Then 助理先列出兩筆請使用者指定，不猜
```

### US-07 — 代辦的共通規矩 [P0]
**As a** 使用者, **I want** 現貨能力沿用既有的代辦規矩, **so that** 助理的行為一致可預期。

```gherkin
Scenario: 拒絕原話帶回
  Given 交易服務因任何規則拒絕一件現貨日誌的事
  When 助理回覆
  Then 內容是交易服務的原話，助理照著改或請使用者決定，不重送一模一樣的內容

Scenario: 別人的交易
  Given 現貨交易 #9 屬於另一位使用者
  When 使用者查看 #9
  Then 助理帶回「找不到」

Scenario: 沒有欄位可以指定擁有者
  When 助理記一筆現貨交易
  Then 這筆一律屬於授權給外掛的使用者，助理沒有任何欄位可以指定擁有者
```

## 4. Business Flow & Logic

- **Core Business Rules（外掛負責的部分）：**
  - 現貨日誌能力與合約日誌能力**各自一組**，名字帶現貨或合約；同一個代號兩本各自獨立。
  - 現貨只有先買後賣、沒有槓桿、沒有方向：使用者說做空或槓桿時助理說明後不送出。
  - 台股以整數股計；「一張」＝1,000 股，換算後說出來請使用者確認；使用者說零股就照股數。
  - 手續費沒說即 0；台股賣出時提醒證交稅併入手續費。
  - 買進價、賣出價必須是使用者說的實際價格，不拿機器人訊息的參考價充當。
  - 修正買賣、修改計畫、寫檢討都是**整份取代**：只改一項時先讀出現值、其餘原樣帶上。
  - 沒說時間以現在為準並以使用者時區回報；沒說統計期間即最近 30 天；列出沒說筆數即最近 20 筆。
  - 標籤兩本共用，沿用既有標籤能力。
  - 其餘規則（一標的一筆持有中、賣出不超過持有、平倉後鎖定、統計口徑）全由交易服務決定並原話帶回。
- **Edge Cases:** 連不到交易服務時說「暫時連不到交易服務」、授權不被認得時請使用者到外掛選單重新連線（沿用既有規矩）。

## 6. Non-Functional Requirements

- **Security:** 沿用外掛授權；沒有任何欄位可以指定擁有者。
- **Performance:** 實盤 vs 回測需要重演，沿用重演的等待上限；逾時不立刻重送。

## 7. Dependencies & Risks

- **External Dependencies:** 交易服務的現貨日誌（`go-trading` 同名切片）須先上線。
- **Known Risks:** 使用者口語的「一張」可能指零股以外的其他單位——一律換算後說出來確認。
