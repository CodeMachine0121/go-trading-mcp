# Product Requirements Document — 回測的槓桿與強制平倉（連接器）

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal

### Problem Statement

交易服務的回測現在算得出槓桿與強制平倉了。連接器**還說不出來**，
而且它是**白名單**——沒有宣告的欄位，助手填了也會被靜靜丟掉。

所以今天助手每一次重演，交出的都是一張「押多少就承擔多少」的成績單。
使用者實際開 5 倍。這讓它錯兩次，而兩次的性質完全不同：

1. **賺賠差了五倍。** 助手推得出來——報酬率乘五。
2. **那個帳戶會在中途歸零，而成績單完全不知道。** 助手**推不出來**，
   因為後面那幾十筆交易根本不存在，卻照樣被算進報酬率。

第 2 件是這一刀的理由。它不噴錯、不看起來怪，就是交出一張
**完全合理、但描述一個早就不存在的帳戶**的表。

### Expected Outcome

- 兩支重演能力都多兩個選填欄位，而且**真的到得了交易服務**。
- 說明寫出助手送出去之前查不到的六件事。
- 兩支能力都說得出 `liquidationExitCount` 是什麼、以及為什麼非看不可。
- **兩格都不填時，送出去的內容與這一刀之前一字不差。**

### Out of Scope

- **連接器自己驗證任何一格。** 它從不決定一個值是什麼意思；
  「現貨開不了槓桿」「維持保證金率超過上限」都由交易服務拒絕，連接器只負責**說出來**。
- 資金費率（交易服務還沒有）、機器人 `positionPlan` 裡那一格槓桿（另一件事）。

---

## 2. User Personas

- **Primary:** 透過這個連接器操作交易服務的**助手**。它看不到使用者的券商、
  看不到成績單以外的任何東西，只讀得到欄位說明。
- **Secondary:** 那位使用者。他讀到的是助手轉述的結論。

## 3. User Stories & Acceptance Criteria

### US-01 — 兩支重演都問得出槓桿 [P0]

**As a** 助手，**I want** 在兩支重演能力上都說得出要開幾倍，
**so that** 我交出的成績單講的是使用者真的會開的那種倉。

```gherkin
Scenario: 重演一支策略腳本說得出槓桿
  Given 能力清單裡的「重演一支策略腳本」
  When 看它有哪些可填的欄位
  Then 有一格叫槓桿倍數，選填
  And 有一格叫維持保證金率，選填

Scenario: 重演一份交易策略說得出同樣兩格
  Given 能力清單裡的「重演一份交易策略」
  When 看它有哪些可填的欄位
  Then 有同樣那兩格，而且說明一字不差

Scenario: 槓桿與交易模式恰恰相反
  Given 能力清單裡的「重演一份交易策略」
  When 看它有哪些可填的欄位
  Then 沒有交易模式那一格
  And 仍然有槓桿那兩格

Scenario: 填了的槓桿真的到得了交易服務
  Given 助手在一次重演裡填了槓桿倍數 5
  When 連接器把這件事轉給交易服務
  Then 送出去的內容裡帶著槓桿倍數 5

Scenario: 兩格都不填時送出去的內容一字不差
  Given 助手一次重演裡兩格都沒填
  When 連接器把這件事轉給交易服務
  Then 送出去的內容裡沒有槓桿倍數
  And 送出去的內容裡沒有維持保證金率
```

### US-02 — 說明寫出送出去之前查不到的事 [P0]

**As a** 助手，**I want** 欄位說明告訴我那幾件我猜不到的事，
**so that** 我不會交出一張看起來合理、實際上描述另一個帳戶的成績單。

```gherkin
Scenario: 說得出留白是什麼意思
  Given 槓桿倍數那一格的說明
  When 讀它
  Then 它說出不給、給 0 或給 1 都是不借錢，也不模擬強制平倉

Scenario: 說得出撐得住多遠，並給實際數字
  Given 槓桿倍數那一格的說明
  When 讀它
  Then 它說出撐得住的距離大約是 100 除以槓桿個百分點
  And 它舉出至少一個實際數字，例如 5 倍約 19.5%

Scenario: 說得出止損比強平近時止損先出場
  Given 槓桿倍數那一格的說明
  When 讀它
  Then 它說出開了槓桿就該一起給止損距離

Scenario: 說得出現貨開不了槓桿
  Given 槓桿倍數那一格的說明
  When 讀它
  Then 它說出現貨交易模式給大於 1 會整次被拒絕

Scenario: 維持保證金率留白不是關掉它
  Given 維持保證金率那一格的說明
  When 讀它
  Then 它說出留白時是 0.5%
  And 它說明這與隔壁那幾組留白的意思不一樣

Scenario: 說得出上限是算出來的
  Given 維持保證金率那一格的說明
  When 讀它
  Then 它說出必須小於 100 除以槓桿
```

### US-03 — 成績單多的那一格要看得懂 [P0]

**As a** 助手，**I want** 知道成績單上多出來的那一格是什麼，
**so that** 我分得出「停損一直在擋」與「這個帳戶歸零過三次」。

```gherkin
Scenario: 重演一支策略腳本說得出那一格
  Given 「重演一支策略腳本」這個能力的說明
  When 讀它
  Then 它說出成績單上有強平出場筆數
  And 它說出為什麼非看不可

Scenario: 重演一份交易策略說得出同一件事
  Given 「重演一份交易策略」這個能力的說明
  When 讀它
  Then 它說出同一件事，措辭與另一支一字不差
```

## 4. Business Flow & Logic

### Core Business Rules

**R1 — 兩格放在兩支共用的那一組參數裡。** 不是各自加一次。
兩支重演對這兩格的規則完全相同，寫兩份遲早會有一份先改。

**R2 — 連接器不驗證。** 它從不決定一個值是什麼意思；
規則的唯一擁有者是交易服務。連接器的工作是**宣告**與**轉達**。

**R3 — 留白的不上線。** 這不是連接器新加的規則，是它既有的行為
（`EncodedSubset` 只收填過的名字）。所以兩格都不填時送出去的內容自動一字不差。

**R4 — `liquidationExitCount` 那段說明兩支共用一份。**
與交易成本那段同一個理由：兩份措辭有一天只有一份會被改好，
而那時兩支重演會對同一張成績單講出兩種話。

### Edge Cases

| 情況 | 行為 |
| :--- | :--- |
| 助手填了槓桿卻沒填維持保證金率 | 兩者各自轉達；沒填的那一格不上線，交易服務給它預設值 |
| 助手在現貨模式下填了槓桿 | 照送；交易服務拒絕，原話轉述 |
| 助手填了一個交易服務會拒絕的維持保證金率 | 同上 |
| 交易服務回來的成績單沒有那一格（舊版） | 原樣轉述，連接器不補 |

## 5. UI/UX Design & Interaction

沒有畫面。助手讀到的**就是**欄位說明，所以說明的措辭就是這一刀的介面。

- 槓桿那一格要交代六件事，是這張清單上最長的一段說明。
  它長是因為它守的是一個**看不見的錯誤**——其餘每一格猜錯都會現形，這一格不會。
- 那段成績單說明與交易成本那一段並列，兩支重演共用同一份。

---

## 6. Non-Functional Requirements

- **相容性（最重要）：** 兩格都不填時，送出去的內容與這一刀之前一字不差。
- **一致性：** 兩支重演能力對這兩格的說明逐字相同。
- **不新增驗證：** 連接器不因為這一刀而開始判斷任何一個值。

---

## 7. Dependencies & Risks

### Dependencies

- 交易服務的兩支重演端點已經收得下這兩格、成績單已經有那一格。

### Risks

| 風險 | 緩解 |
| :--- | :--- |
| 忘了宣告，助手填了被靜靜丟掉 | 這正是這一刀存在的理由；有「填了真的到得了」的驗收情境 |
| 兩支說明漂移 | 放進共用的那一組參數、說明抽成共用常數；有「一字不差」的驗收情境 |
| 說明太長沒人讀 | 六件事各自獨立成句，最要緊的兩件（留白的意思、要一起給止損）排在最前面 |
| 連接器開始自己驗證 | 明列在 Out of Scope，並在 R2 寫出理由 |
